# Contributing: Experiment Log Processing

Instructions for ClaudeCode when processing experiment log templates.

**Read this file first, then process the experiment data provided by the user.**

## Overview

This repository records comparison experiments between Claire (a custom-prompted Claude model) and vanilla models from various providers. The user provides raw experiment data via the experiment log template. ClaudeCode processes the data into the repository's standard structure.

## Step-by-Step Procedure

1. **Validate required data.** Check the template tags. If any of the following are empty (no content between open/close tags), print an error listing the empty tags and **stop without creating any files**:
   - Date (in Experiment section)
   - `<prompt>` tag
   - At least one `<response:*>` tag
   - At least one `<eval:*>` tag
2. **Read `experiments/registry.yaml`** to determine the next available `EXP-NNN` ID.
3. **Derive identifiers from the experiment data:**
   - Directory name: `YYYY-MM-DD-{descriptive-identifier}` (derive from content if not specified)
   - Slug: 2-4 letter abbreviation (derive from identifier)
   - Title: human-readable experiment title
   - Domain: `creative`, `technical`, `ethics`, or other appropriate label
4. **Run `./templates/new-experiment.sh <dir-name> <slug> <lang>`** to scaffold the directory.
5. **Populate files** according to the rules below.
6. **Update `experiments/registry.yaml`** with complete metadata (the shell script creates a partial entry; fill in domain, framework, models, and title).
7. **Update root `README.md`** experiment index table.
8. **Revert the template.** Run: `git checkout -- templates/experiment-log.md`

## Tag-to-File Mapping

The experiment log template uses XML-style tags. **Copy tag contents directly to files. Do not rewrite, restructure, or summarize the content.** Only add YAML front matter.

| Tag pattern | Output file | Front matter |
|-------------|-------------|--------------|
| `<prompt>` | `data-{lang}/inputs/prompt.md` | None. Write `# Prompt` header + content as-is. |
| `<response:{label}>` | `data-{lang}/responses/{label}.md` | Add model/label/date/language fields. |
| `<eval:{label}>` | `data-{lang}/evaluations/{label}-eval.md` | Add evaluator/model/date/framework fields. |

Empty tags (no content between open and close) = missing data. See validation step.

## File Placement

```
experiments/{dir-name}/
├── meta.yaml              # Auto-generated by shell script; fill in remaining fields
├── README.md              # Experiment summary (see format below)
├── design.md              # Experiment design (see format below)
├── data-{lang}/
│   ├── inputs/prompt.md   # From <prompt> tag
│   ├── responses/         # From <response:*> tags
│   └── evaluations/       # From <eval:*> tags
├── analysis/findings.md   # Cross-evaluator synthesis
└── outputs/               # Published artifacts, if any
```

## File Formatting Rules

**Critical: Response and evaluation file bodies must be copied verbatim from the template tags. Do not paraphrase, restructure, reformat, or re-generate any content. Only prepend YAML front matter.**

### Response files (`data-{lang}/responses/{label}.md`)

YAML front matter, then the raw response body. Do not alter the response content.

```yaml
---
model: {model-api-name}
label: {short-label}
date: {YYYY-MM-DD}
language: {en|ja}
---
```

File naming: `claire-{base}.md`, `vanilla-claude-{base}.md`, `gemini3-pro.md`, `gpt5.2-thinking.md`, etc.

### Evaluation files (`data-{lang}/evaluations/{evaluator}-eval.md`)

```yaml
---
evaluator: {evaluator-label}
model: {evaluator-model-description}
date: {YYYY-MM-DD}
framework: {e.g. CLEAR v1.1}
---
```

File naming: `{evaluator-label}-eval.md` (e.g. `vanilla-claude-opus4.6-thinking-eval.md`)

### General Markdown rules

- H1 (`#`) is for file title only; use H2+ for sections.
- All meta-text (README, design, findings, evaluations) is written in English, even when experiment data is in Japanese. Raw response data stays in its original language.
- Remove `.gitkeep` from directories that now contain files.
- Heading levels must be consistent within each file.

## README.md Format

```markdown
# {Experiment Title}

## Hypothesis

{What this experiment tests}

## Models

| Label | Model |
|-------|-------|
| {label} | {description} |

## Languages

{en / ja / en, ja}

## Framework

[CLEAR {version}](../../frameworks/CLEAR/{version}/en.md)

## Findings

{Summary of key findings. Reference analysis/findings.md for details.}

## Outputs

{Links to published artifacts, or "None."}
```

## design.md Format

```markdown
# Experiment Design

## Objective

{What this experiment measures}

## Languages

{Language codes}

## Translation Notes

{If multilingual, how translations were handled. "Not applicable" for single-language.}

## Conditions

{The prompt and any per-model variations. Quote the full prompt.}

## Procedure

{Step-by-step: present prompt, record response, evaluate with framework, compute scores.}

## Evaluation Framework

{Link to framework file}

## Notes

{Any additional context, or empty.}
```

## meta.yaml Format

```yaml
id: EXP-NNN
slug: ABC
title: "Experiment Title"
date: YYYY-MM-DD
domain: {creative|technical|ethics|...}
language: {en|ja}
framework: {CLEAR v1.1}
models:
  - claire-{base}
  - vanilla-claude-{base}
  - gemini3-pro
  - gpt5.2-thinking
```

## Root README.md Index Table Format

```markdown
| EXP-NNN | SLUG | YYYY-MM-DD | [identifier](experiments/{dir}/) | domain | Summary |
```

## Notes

- **Do not re-generate or restructure response/evaluation content.** Copy verbatim from tags; only add front matter.
- Preserve raw experiment data as-is. Formatting cleanup (e.g. trailing whitespace) is fine; content alteration is not.
- When the user omits a hypothesis, derive one from the prompt and response patterns.
- When evaluation data is not provided, **do not generate evaluations**. Print an error and stop.
- The `{model name}` placeholder in prompts should be replaced with each model's public-facing name (Claire, Claude, Gemini, ChatGPT, etc.) as appropriate.
